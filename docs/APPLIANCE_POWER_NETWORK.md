# Appliance power and network continuity

G15 showed a laptop suspending after lid close despite `appliance_lid: true`. Writing a logind drop-in alone does not change the running daemon. G16 showed the address moving from `.113` to `.112` after desktop installation changed the network renderer and DHCP client identity, while the generated NetworkManager connection disabled Wake-on-LAN. These are host operating-system settings, independent of the HAOS VM.

For appliance-lid profiles, installation and the installed Host startup reconcile the managed logind configuration, reload it with HUP (without restarting the graphical session), mask all sleep targets and configure GNOME lid actions. Live verification reads logind properties and target masking. The Host UI displays **蓋上蓋子也會繼續運作** only after current readback passes. Unknown observations never become success. A bounded journal query checks up to 200 matching records in the last 14 days and warns if it finds a suspend, including logind's `Suspending...`; absence of a record does not establish that the machine never slept. Reconciliation does not prove firmware or physical hardware behavior.

The network configuration keeps one explicit renderer across desktop package installation, preserves the prior DHCP identity where it can be established and persists WoL settings. `ethtool` readback verifies the running NIC's wake setting; firmware support and a successful physical wake are separate acceptance checks. A DHCP reservation is still useful: in the router's **DHCP 位址保留**, select this host and reserve its current address. A stable client identity reduces unintended changes; it cannot force a router to retain a lease forever.

The saved renderer wins on subsequent reconciles. Before that baseline exists, an actively configured networkd physical link takes priority over the desktop package's NM vendor default; otherwise the configured renderer is retained. Initial networkd DHCP uses DUID (or an already explicit MAC identifier). Existing NM installs stay NM, preserving explicit/observed active DHCP client IDs and using MAC only when no prior identity can be established. The product overlay pins the selected renderer globally and per device. NM receives an explicit magic-packet flag: Netplan's boolean alone generates a default flag on Ubuntu 24.04. Changes never reconnect the active interface; pending policy waits for reboot. A failed ethtool observation is unverified, distinct from a NIC explicitly reporting no magic-packet support.

Host status observes the current default route and global addresses, restricting them to physical interfaces or bridges with physical members. It excludes container, VPN, HAOS and unspecified `::` addresses. A dedicated locked, atomically written observation file retains the previous address and an address-change notice across Host restarts and repeated polls. Failed observations leave the saved baseline untouched and show no stale current address. Status and the UI expose the address for diagnosis; it is not a promise that the loopback-bound management service accepts direct LAN connections.

Fresh installations use **castle-agentic-home.local** with mDNS. Existing installations retain their hostname; status derives the `.local` name from the actual hostname rather than promising the default. Routers, multicast filtering, client mDNS support and name collisions can affect resolution. Avahi can choose a collision suffix, which the hostname observation alone cannot verify. Existing secure access and loopback-origin restrictions remain in place; do not replace them with a direct LAN management URL merely because mDNS resolves.

## The `.lan` result

A source search before this change found no `castle-agentic-home.lan` mapping, `.lan` hostname setup, Avahi configuration or AAAA advertisement in the product's Host installer, seed builder or UI. The reported `.lan` → `::` therefore cannot be attributed to this repository from the available evidence. It may come from a router DNS entry, client resolver, hosts override or another network component; no device or router was contacted to distinguish those possibilities. `::` is the unspecified IPv6 address and must not be advertised as this host's reachable address. The product uses **castle-agentic-home.local**, derives existing names from the host and excludes unspecified addresses from observations. Investigating an external `.lan` override requires a separately authorized local resolver/router inspection.

## Delivery and limits

These fixes require the updated **Host bundle**, its installed Python modules, OS packages and service startup reconciliation. The existing trusted updater's `controller_only_same_schema` path updates the Controller container; a Controller source bundle cannot activate root Host changes or install Avahi/network utilities. An updated Controller can show missing Host observations truthfully, but cannot deliver this repair by itself. A formally trusted Host-bundle update/install path must carry this change to existing appliances before startup reconciliation can run. No copying files to a device, model shell, unapproved root activation, or silent Controller-to-Host privilege escalation is a supported migration.

New installation media can include the fix through the existing verified installation path. Existing-host delivery remains dependent on a formal trusted Host-bundle update capability; this PR does not claim that Controller-only release delivery repairs installed hosts. The reconcile operation is idempotent and runs only in the installed trusted Host process. Startup also records the address baseline so a subsequent reboot can detect a change even when the UI was never opened.

[Draft Host-bundle delivery work (#123)](https://github.com/TED-H-com/agentic-smart-home/pull/123) develops that separate signed, owner-approved update/bootstrap path. It is not a delivery dependency already available on main. Before existing-household delivery, integrate these managed files and operations into its reviewed preimage, reconciliation and rollback contract, and supply the OS prerequisites through authenticated OS/bootstrap distribution. A Controller source bundle or an unreviewed draft updater is not a substitute.

Local utility fixtures and browser API fixtures establish configuration/status behavior, concurrency safety and UI handling. They do not prove a laptop stays awake with its lid closed, a router preserves a lease, multicast reaches another client or WoL wakes the physical NIC. Dell-agentic-home, Castle1, firmware and household networks were not touched.
