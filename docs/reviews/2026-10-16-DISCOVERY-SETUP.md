# 接入進度與讀回（2026-10-16）

使用者離開探索清單到 HA 原生設定後，原本沒有保存正在接入哪個候選，也無法區分候選消失與接入成功。本增量提供共用接入追蹤：保存精簡候選，回來由 Owner 選定整合實例，重新讀取關聯設備與 API 狀態。正式產品與公開示範沿用同一介面。

## 範圍與設計

- 唯讀 HA adapter 保持原範圍，設定與帳號授權在固定 HA 原生入口完成。沒有新模型工具、家庭 policy 或 HA 設定／設備寫入。
- Controller 的私有 `discovery_setup` v1 保存候選、同類整合起始清單及選擇；不保存整屋快照。SQL schema 保持 3，舊 binary 忽略但不清理此 kind，詳見 [資料相容性](../RELEASE_POLICY.md#接入追蹤資料相容性d3b)。
- 持久 scope 綁定 Owner 與 HA token／來源；短期登入世代另做請求檢查。建立、選擇與忘記採原子去重收據，選擇／忘記採 revision 檢查，回應落盤後重驗即時 Owner 與 Host／bridge authority。
- API 列表至多 20 筆；選項與設備各至多 100 筆。來源不完整保留未知；可用狀態是關聯設備的 HA entity 觀測，不是全部整合功能或物理動作證明。
- UI 延後讀取、無預選整合、錯誤不重標舊資料、晚到回應隔離；外層與側欄使用同一元件。公開示範資料只存在瀏覽器記憶體，重載會重設。

## 驗證

實作驗證進行中；結果完成後更新此節。測試一律經磁碟暫存 wrapper，測試容器及服務隨測試清理。真品牌帳號、實體家庭、多來源掃描與既有 ISO 更新不在本輪證據範圍；32 案維持 2 passed、30 not_run。
