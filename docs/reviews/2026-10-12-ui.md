# 2026-10-12：Web／onboarding 整合審查

審查基準：`0.5.0`、HEAD `90d3054`，以及本輪尚待整合的修正。範圍是實際 Controller、Gateway transport、Web 假設與安裝／Plan 文件；沒有修改六份 v3 原稿。這不是 Owner 家庭或真雲端帳號驗收。

## 已重現並修正的問題

### UI-R1 — HA 授權失敗留在帶 code 的回呼網址（P2）

原先只有成功完成 `finish()` 才會 redirect。授權已過期、格式不符時回傳 JSON 400；主機 session 已過期時由 middleware 回傳 JSON 401。使用者離開引導，網址保留 `state`／`code`，與原來宣告的乾淨返回流程不符。Controller 正式啟動已停用 access log，因此本次沒有證據顯示 code 寫入正式 access log。

修正 [ha_oauth.py](../../controller/agentic_controller/ha_oauth.py) 與 [app.py](../../controller/agentic_controller/app.py)：已登入但拒絕的回呼，以及未登入的固定 GET 回呼，都以 303 返回 `/#onboarding`，加上 `no-store`、`no-referrer`。未登入分支不取得 session、不交換 code。當前且仍有效的 state 被取消時保存安全失敗狀態；偽造／被取代的 state 不覆寫新流程。不增加自動重試或自動建立新 grant。

新增測試使用實際 Controller ASGI middleware、cookie、CSRF 與 OAuth 路由。過期 grant、過期 session、格式錯誤及取消均確認乾淨 Location；拒絕路徑的憑證交換呼叫次數為零。原有 service-level scope／重播拒絕測試仍保留。

### UI-R2 — Telegram 初次同步可能吞掉剛顯示的配對碼（P2）

Gateway 先建立一次性 code，再啟動 receiver。原 transport 在 `getMe`／webhook 檢查後，以 `offset=-1` 略過最新訊息；使用者在這幾次 HTTP 往返期間送出的 `/pair CODE` 可能剛好是被略過的一筆。純 `/api` UI fixture 沒有覆蓋這個 transport 時序。

修正 [channels.py](../../controller/agentic_controller/channels.py)：首次讀取最多最近 100 筆，只將 `/pair ` 文字交給既有 Gateway 的當次 code、期限、設定摘要與 sender／chat 驗證；一般歷史訊息仍完全略過。即使配對碼後面接著一筆普通訊息，也能在同一批建立正確綁定。首次讀取失敗不顯示 connected。負 offset 與 100 筆上限依 [Telegram 官方 getUpdates 契約](https://core.telegram.org/bots/api#getupdates)。

新增測試直接執行實際 Gateway、SQLite 持久狀態及 TelegramTransport，只替換 Telegram HTTP 回應：有效 code、後接普通訊息、錯誤／過期 code、bot sender 與普通歷史。只有有效當次 code 可以完成配對；全部案例都沒有模型呼叫。這仍不是 Telegram 真帳號測試。超出首批 100 筆的舊更新不會被重播，極高流量聊天室需重新送出尚有效的配對碼。

## Plan／安裝方向核對

- [安裝](../../INSTALL.md) 與 [onboarding](../ONBOARDING.md) 已區分 firstboot 外層可用、CLI 固定查證、Hermes 獨立認證、通道實際連線、原生 HA 帳號及 owner 授權。Web 跳過通道、既有手動設定仍可用；綁定 household 的權杖不交給模型。
- [Plan](../../PROJECT_PLAN.md)／[進度](../v3/PROGRESS.md) 正確保留 E1／E2 未完成。固定 bootstrap CLI 回覆、Host 離線 sandbox、HAOS VM lifecycle 都不能當作兩個自主 coding workers、隔離 candidate preview、正式更新／退版已交付。
- 最新 Hermes 準備是「未使用安裝」的首次啟用程序。已登入／已使用的部署不能靠這條路徑更新；安裝文件也未承諾原地 upgrade。後續 fixed updater 仍是必要工作。
- LINE 目前會略過登入帳號自己的訊息以防回音，因此實際配對／日常對話需由另一個允許的帳號送出。文件建議使用次要 LINE 帳號，但真帳號驗收仍應明確檢查這個使用前提。
- LAN bridge／mDNS、Matter／USB、Owner laptop 的 UEFI／散熱／磁碟與真雲端 OAuth 尚需各自的現場證據。一次性 VM 和協定 fixture 不能合稱完整家庭端到端驗收。
